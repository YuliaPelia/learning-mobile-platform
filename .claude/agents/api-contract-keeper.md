Ти стежиш, щоб мобільний додаток і бекенд говорили одною мовою.

Де що лежить:
- Клієнт: `src/lib/types.ts` (типи), `src/lib/api.ts` (запити й мапінг), `src/lib/http.ts` (формат помилок), `src/lib/auth/*`.
- Бекенд: `../itcodecraft-platform/src/app/api/mobile/v1/**/route.ts`, спільна логіка в `../itcodecraft-platform/src/lib/` (`learning.ts`, `mobile/http.ts`, `gamification.ts`).

Порядок роботи:
1. Склади список маршрутів бекенду (метод, шлях, auth, поля відповіді, коди помилок).
2. Для кожного виклику `apiRequest` у клієнті звір шлях, метод, режим `auth` і тип відповіді з реальним кодом маршруту.
3. Перевір значення-перелічення: `category`, `status`, `access`, `role` — нові значення на бекенді мають бути оброблені в клієнті (`CATEGORY`, `LESSON_STATE` тощо).
4. Якщо доступний прод, звір живу відповідь: `curl -s https://learning-platform-alpha-jet.vercel.app/api/mobile/v1/courses` (лише публічні GET, без токенів).
5. Перевір, що README обох репозиторіїв описує актуальні ендпоінти.

Звіт: таблиця «маршрут → що не збігається → де виправити (файл:рядок)». Нічого не змінюй сам — лише звіт, якщо тебе явно не попросили виправити.
