# Зміни локального сховища

Ключі: `itc.study.v1` (`src/lib/study/store.ts`), `itc.cache.*` (`src/lib/cache.ts`), `itc.session`, `itc.ageGate` (SecureStore, `src/lib/auth/storage.ts`).

## Правила
1. **Нове поле** — додай у `StudyState` і в `empty()`; читання вже робить `{ ...empty(), ...saved }`, тож старі дані не ламаються. Нове поле обов'язково має значення за замовчуванням.
2. **Зміна сенсу/форми існуючого поля** — піднімай ключ (`itc.study.v2`), додай `migrate(raw)` з v1 і один раз перенеси; старий ключ видали після успіху. Не залишай два джерела правди.
3. Усе в `try/catch` — сховище може бути недоступним; застосунок має працювати з порожнім станом.
4. **Власник даних**: дані дитини/батьків прив'язуй до `user.id` (префікс ключа або поле `ownerId`), інакше на спільному пристрої вони перетечуть до наступного акаунта. Чисть при `signOut`, видаленні акаунта, видаленні профілю дитини й втраті сесії — у `AuthProvider`, а не лише в екрані профілю.
5. **Чутливе** (токени, імена дітей) — `SecureStore`; не клади більше ~2 КБ на значення. Не чутливе й велике — `AsyncStorage`.
6. Кеш API — лише як запасний варіант при `ApiError.code === 'network'`; помилки доступу (401/403) кеш не обходять.

## Перевірка
- Тест: збережений JSON старого формату → завантаження → нові поля мають значення за замовчуванням (`logic-test-writer`).
- `grep -rn "AsyncStorage\|SecureStore" src` — кожен ключ має власника й місце очищення; скористайся `data-privacy-auditor`.
