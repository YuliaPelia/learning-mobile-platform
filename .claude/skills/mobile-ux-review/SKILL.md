# Мобільний UX: як проєктувати й перевіряти екран

Доповнює `theme-tokens` (вигляд), `child-psychology-ux` (тексти й мотивація для 9–17) і `ui-a11y-auditor` (контраст, a11y). Тут — **поведінка й зручність**. Перед роботою з Expo API звіряйся з документацією поточного SDK (`AGENTS.md`).

## 1. Одна головна дія на екран
- Є одна очевидна первинна дія (білий/фіолетовий `Button` primary); решта — `outline` або текстові.
- Первинна дія — у нижній третині екрана (зона великого пальця), не в шапці. Деструктивні дії (вихід, видалення) — далеко від первинної, із підтвердженням.
- Не більше 3–4 варіантів вибору на екрані без групування; довгі списки — секціями із заголовками.

## 2. Усі стани, не лише «щасливий»
Для кожного екрана з даними перевір і реалізуй:
| Стан | Як у проєкті |
|---|---|
| Завантаження | `Skeleton`, не порожній екран і не спінер на весь екран |
| Порожньо | `Robot pose="think"` + одне речення «що робити» + кнопка дії |
| Помилка мережі | зрозумілий текст без техніки + «Спробувати ще» + `pose="sad"` |
| Офлайн | кеш показуємо, зміни не губимо, без модалок-«ляпасів» |
| Частковий успіх | покажи те, що є; помилку — вбудованим рядком |
| Довгі дані | довгі імена/назви курсів не ламають верстку (`numberOfLines` + запас) |

## 3. Навігація й жести
- Expo Router: `router.push` — вглиб, `router.replace` — після входу/виходу/покупки (щоб «назад» не повертав на завершений крок).
- «Назад» завжди працює: системний жест iOS (свайп від краю) і кнопка Android. Не блокуй його без причини; якщо є незбережені дані — підтвердження.
- Нижня панель — лише для 3–5 розділів верхнього рівня; глибші екрани лежать у стеку над нею.
- Жести-швидкості (свайп, довге натискання) — тільки додатково; кожна дія доступна й звичайним дотиком.
- Модалки/листи — для короткої незалежної задачі; потік із кількох кроків — окремі екрани.

## 4. Дотик і зони
- Ціль ≥ 44×44 pt, між сусідніми цілями ≥ 8 pt (діти — менш точні пальці).
- Безпечні зони: `useSafeAreaInsets` / `Screen`; нічого важливого під «острівцем», домашньою смугою й плаваючою панеллю (`paddingBottom: 120` у `Screen`).
- Стан натискання видно одразу (`PressableScale`, ≤ 100 мс); довга операція — стан «завантаження» на самій кнопці, і повторне натискання вимкнене.

## 5. Форми й клавіатура
- Правильний `keyboardType`, `textContentType`, `autoComplete`, `returnKeyType`; Enter переходить до наступного поля чи надсилає.
- Екран з полями прокручується (`ScrollView` + `keyboardDismissMode`, `automaticallyAdjustKeyboardInsets`) — кнопка «Далі» не ховається за клавіатурою.
- Помилка — біля поля, текстом (не лише червоним), після втрати фокуса або спроби надіслати; не лякай до того, як людина дописала.
- Мінімум полів; не питай того, що вже знаєш. Для дітей — без зайвих персональних даних (див. `data-privacy-auditor`).

## 6. Відгук і прогрес
- Кожна дія має видимий результат за ≤ 1 с: зміна стану, вібрація (`src/lib/haptics.ts`), коротке повідомлення.
- Прогрес багатокрокового потоку (квіз, онбординг) видно: «3 з 5» + смужка `AnimatedBar`; можна повернутись назад або пропустити.
- Помилку користувача (неправильна відповідь) подавай як підказку до навчання, не як покарання (`child-psychology-ux`).
- Деструктивну дію можна скасувати (undo) або вона з підтвердженням, що називає наслідок («Задачі на цьому пристрої зникнуть»).

## 7. Платформи
- iOS: великі заголовки, свайп-назад, системні листи/меню, шрифт SF/системний для довгого тексту.
- Android: кнопка «Назад», `StatusBar`/edge-to-edge, тінь = `elevation`, перевір на малому екрані (360×640).
- Не імітуй чужу платформу в деталях; користуйся нативними компонентами (`Switch`, `DateTimePicker`, `expo-router` Stack/Tabs).

## 8. Швидкість
- Списки — `FlatList`/`FlashList` з `keyExtractor` і стабільними `renderItem`; не `ScrollView` + `map` для довгих даних.
- Картинки — `expo-image` з розміром і кешем; не вантаж оригінали 4000 px.
- Анімації — на UI-потоці (Reanimated/`useNativeDriver`); без анімації `width`/`height`.
- Перший екран показується без очікування мережі (скелетон, кеш).

## 9. Особливо для дітей 9–17 і батьків
- Діти: коротко, конкретно, одна думка на екран; без темних патернів (відлік, «ти втратиш серію», сором).
- Батьки: окремий спокійний тон, дорослі терміни ок; усі покупки й зовнішні посилання — за `ParentalGate`.
- Перемикач вигляду «play/pro» (`useSkin`, `makeStyles`): новий екран перевір в обох.

## Як проводити рев'ю екрана
1. Прочитай файл екрана та компоненти, які він використовує.
2. Пройди розділи 1–9 і запиши лише **реальні** проблеми з `файл:рядок`.
3. Класифікуй: **блокер** (користувач застрягає, втрата даних, ціль <44 pt) · **важливо** (немає стану, незрозумілий текст) · **дрібниця**.
4. Для контрасту й VoiceOver — делегуй `ui-a11y-auditor`; для текстів дитині — `child-psychology-ux`.
5. Звіт: таблиця «екран · проблема · вага · виправлення». Виправляй лише за запитом; після правок — `npx tsc --noEmit` і `npx expo lint`.
