## Ухвалені рішення

### 1. Локальні дані при виході — ЧИСТИМО, потім синхронізуємо з сервером (28–29.10.2026)
- **Зараз:** задачі, сесії таймера, результати квізів, помилки, цілі дітей лежать лише на пристрої (`src/lib/study/store.ts`, ключ `itc.study.v2.<власник>`). **При виході з акаунта вони стираються** (`StudyBridge` у `src/app/_layout.tsx` + підтвердження в `profile.tsx`); при видаленні акаунта — теж.
- **Наслідок:** поки немає синхронізації, вихід = втрата цих даних (користувача про це попереджає діалог). Серверний прогрес (уроки, XP, серія) не страждає.
- **Потрібно зробити:** синхронізація з сервером, після чого прибрати попередження. План:
  1. Бекенд `../itcodecraft-platform`: таблиці/ендпоінти `/api/mobile/v1/study/*` — задачі, сесії фокусу, результати квізів (+ відповіді для повторення помилок), цілі дітей. Скіл `new-mobile-endpoint`.
  2. Клієнт: `store.ts` стає кешем над API (черга офлайн-змін, злиття за `id`/часом); міграції за скілом `storage-migrations`.
  3. Квізи — з БД (створює викладач/менеджер), тестовий квіз `src/data/quizzes.ts` видалити.
  4. Після синхронізації: перевірити, що чистка при виході не втрачає даних (спершу відправити чергу, потім стерти), оновити `data-privacy-auditor`.

### 2. Оплата — В САМОМУ ЗАСТОСУНКУ, через IAP (29.10.2026)
- **Обрано:** власні In-App Purchase без стороннього сервісу — `expo-iap` (StoreKit 2 / Google Play Billing) + перевірка квитанцій на бекенді. RevenueCat відкинуто: для Kids Category небажаний сторонній SDK із збором даних.
- **Чому не WayForPay в застосунку:** цифрова підписка мусить іти через Apple IAP (3.1.1) / Google Play Billing; картка в застосунку = відмова. WayForPay лишається на сайті. Тексти «оплата на сайті» зі застосунку прибрано (3.1.3).
- **Ціни (з сайту, грн/міс):** Простий (`basic`) 249, Середній (`standard`) 449, Преміум (`premium`) 899. У магазинах ціни задаються власними ціновими рівнями (UAH), точні значення можуть відрізнятись; комісія Apple/Google 15–30% зменшує виручку.
- **Побудовано вже:** батьківська перевірка (`src/lib/parentalGate.ts`, `src/components/ParentalGate.tsx`) — на посиланнях на юридичні документи; для покупок підключити, коли зʼявиться екран тарифів.
- **Статус (29.10.2026):** клієнт ЗРОБЛЕНО, але НЕ перевірено на пристрої й вимкнено прапорцем: каталог `src/lib/iap/products.ts` (тести), обгортка `src/lib/iap/service.ts` (`expo-iap`, динамічний імпорт — Expo Go не падає), екран `src/app/(tabs)/(learn)/plans.tsx` (лише батьки, батьківські ворота, відновлення покупок, текст про автопоновлення), пункт «Тарифи й підписка» в профілі, блок «Ваші підписки» зі станом і кнопкою «Обрати курс», екран вибору курсу `choose-course.tsx` (один раз, з підтвердженням; відкривається одразу після покупки «1 курс на вибір»). Вмикається `EXPO_PUBLIC_IAP_ENABLED=1` (додати в `eas.json` разом із релізом). Бекенд (`POST /api/mobile/v1/billing/iap/verify`, `verifyIapPurchase` в `src/lib/api.ts` уже викликає його) — НЕ зроблений: чекаємо коміту власниці в `itcodecraft-platform`, ключів Apple/Google й товарів у магазинах.
- **Рішення (29.10.2026, власниця):**
  - **Модель:** групи підписок за «місцем дитини» — до 3 місць (діти), у кожному 3 тарифи (`basic/standard/premium`, місячні) = 9 товарів. Для `basic/standard` курс обирають ПІСЛЯ покупки (на сервері), а не в магазині. Річних поки немає.
  - **Kids Category — НЕ обираємо** (вік 9–17, самореєстрація від 14, вхід Google/Apple). Лишаємо батьківські ворота на покупках і зовнішніх посиланнях + віковий рейтинг.
  - **Бекенд:** власниця спершу комітить свої зміни в `itcodecraft-platform` (email-коди), потім додається міграція підписки.
- **Товари (створює власниця в App Store Connect / Play Console):** id за схемою `tech.itcodecraft.slot<1-3>.<basic|standard|premium>.monthly`; групи підписок `slot1..slot3`. Каталог у коді — `src/lib/iap/products.ts`.
- **Що ще потрібно від власниці:** Apple Developer + App Store Connect API key (issuer id, key id, .p8), сервісний акаунт Google Play, створені товари, нова dev-збірка (`eas build --profile development`), тестові акаунти sandbox.
- **Бекенд (ЗРОБЛЕНО 29.10.2026; не перевірено на справжніх ключах Apple/Google):** у `itcodecraft-platform` — міграція `20261029120000_iap_subscriptions` (провайдер, externalId, storeProductId, slot), `src/lib/iap/*` (Apple через `@apple/app-store-server-library` із вбудованими кореневими сертифікатами; Google через Play Developer API v2 + `jose`), ендпоінти `POST billing/iap/verify`, `POST billing/iap/apple-notifications`, `POST billing/iap/google-notifications?token=`, `GET subscriptions`, `POST subscriptions/[id]/course`; 32 тести. Змінні середовища — у `.env.example` бекенду (без них 503). Відновлення покупок іде через той самий `verify`. Бекенд закомічено в `itcodecraft-platform` (333e3c0). Курс у запитах — за slug (`courseSlug`).
- **Клієнт:** `expo-iap` (нативний: потрібна dev-збірка, в Expo Go не працює), екран тарифів лише для батьків (дитина не купує), відновлення покупок, юридичний текст про автопоновлення.
